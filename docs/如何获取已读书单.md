# 如何获取自己的已读书单

> 这是《读书小记》的真正第 0 步：先把“我读过什么”变成 AI 能整理的数据。

本项目不要求用户手工重新输入几百本书。优先从自己已有的阅读记录、下载历史或导出文件中建立候选书单，再由 AI 去重、确认和生成权威书目 CURRENT。

---

## 路线 A｜豆瓣读书记录

### 目标

把自己在豆瓣标记过的读书记录导出为结构化或半结构化文件，再交给 AI 整理。

原项目曾实际使用电脑端自制导出工具完成这一步，并成功把完整“已读”记录导入项目。

### 推荐数据字段

导出时尽量保留：
- 书名
- 作者
- 阅读状态（读过 / 在读 / 想读）
- 评分（如有）
- 标记日期（如有）
- 用户短评（如有）
- 豆瓣条目链接（如有）

### AI 整理规则

1. 优先处理“读过 / READ”；
2. “在读 / 想读”不要自动混入已读书单；
3. 同一本作品的不同条目先标记，不要直接粗暴删除；
4. 同名作品需要作者等信息消歧；
5. 用户个人短评与 AI 生成文字必须分开；
6. 整理完成后输出 `BOOKLIST_CURRENT`。

### 不需要原项目的旧插件：让你的 Agent 自建导出工具

原项目曾使用自制工具导出豆瓣读书记录，但公开版不依赖那份旧源码。

如果豆瓣没有适合你的现成导出方式，可以把下面的任务书交给自己的 AI Agent，让它根据你**当前实际看到的网页结构**制作一个最小本地导出工具。

推荐优先级：

1. **最稳妥：保存自己已登录后能看到的读书记录网页 HTML，再让本地脚本解析。**
2. 如果页面允许且用户明确需要，可由 Agent 制作只在本机运行的浏览器辅助脚本/扩展，从当前页面提取可见记录。
3. 不要求用户把账号密码、Cookie、Token 或浏览器会话交给 AI。
4. 不绕过登录、验证码、访问控制或网站技术限制；网页结构变化时重新检查选择器，而不是强行抓取。

#### 可直接复制给 Agent 的任务书

```text
请帮我制作一个“个人豆瓣读书记录导出工具”。

目的：
只整理我自己账号中、我正常登录后能够查看的读书记录，用于制作个人《读书小记》。

优先方案：
先让我用浏览器把自己的读书记录页面保存为 HTML，然后你写一个本地解析脚本，从这些 HTML 中提取数据。除非确有必要，不要做自动登录或网络爬取。

需要提取的字段尽量包括：
- 书名
- 作者
- 阅读状态（读过 / 在读 / 想读）
- 我的评分（如页面存在）
- 标记日期（如页面存在）
- 我的短评（如页面存在）
- 条目链接（如页面存在）

输出：
- UTF-8 CSV
- 同时输出 JSON 备份
- 一条记录一本书
- 保留 source=douban
- 不因为字段缺失而虚构内容

功能要求：
1. 支持一次选择多个我保存的 HTML 文件；
2. 自动合并分页；
3. 基于“条目链接优先，其次书名+作者”去重；
4. 保留原始字段，无法解析的字段留空；
5. 输出解析成功数、重复数、失败数；
6. 对失败项输出原因，方便人工检查；
7. 不上传我的阅读记录到第三方服务器，默认全部在本机处理；
8. 不读取或要求我的密码、Cookie、Token；
9. 不绕过登录、验证码、访问控制或网站技术限制；
10. 先用1个HTML做最小测试，确认字段正确后再批量处理。

请先查看我提供的实际 HTML 结构，再决定 Python、JavaScript 或浏览器扩展哪种实现最简单。不要凭空假设网页 DOM 结构。
```

#### 完成后的验收

不要只看“脚本运行成功”。至少随机抽查 5–10 本书，对比网页原记录，确认书名、作者、状态、评分等没有串行或错位。

随后把 CSV/JSON 交给《读书小记》Skill，进入 BOOKLIST_CURRENT 阶段。

## 路线 B｜Z-Library 下载历史

> 下载历史只能证明“下载过”，不天然等于“读完”。是否把它视为已读，由用户自己决定。

### 原项目实际使用的方法

原项目的下载历史共有 4 页：

```text
50 + 50 + 50 + 5 = 155 条
```

在电脑浏览器中逐页打开自己的下载历史，然后：

1. 每一页使用浏览器 **Ctrl+S**；
2. 保存网页 HTML；
3. 4 页分别保存；
4. 交给 AI 读取；
5. 配套生成的 `xxx_files` 资源文件夹不是书单解析的必要输入，可不提交给 AI。

### 为什么保存 HTML

HTML 中通常已经包含页面显示的书名、作者等文本。相比截图，HTML 更适合 AI/程序批量提取、去重和核对，也避免手工抄录。

### AI 处理流程

```text
下载历史 HTML
      ↓
提取书名 / 作者
      ↓
作品级去重
      ↓
与豆瓣 READ 去重
      ↓
与已有《读书小记》卷册去重
      ↓
得到“下载过但豆瓣可能漏标”的候选
      ↓
按用户自己的阅读判定规则确认
      ↓
BOOKLIST_CURRENT
```

### 阅读判定规则

原项目作者个人采用过：

> “Z-Library 有下载记录 = 默认已读完”

这是**个人工作流规则，不是本 Skill 的通用事实**。

新用户第一次使用时，AI 必须让用户选择：

- **严格模式**：下载记录只算“候选”，用户确认后才进入已读；
- **个人规则模式**：用户明确声明“我的下载记录默认都视为已读”后，AI 才可批量加入。

AI 不得自行假定“下载 = 已读”。

## 路线 C｜手工书单或其他来源

如果没有豆瓣/Z-Library，也完全不影响使用。

用户可以提供：
- TXT / Markdown 书名列表；
- CSV / Excel；
- 其他阅读 App 的合法导出文件；
- 自己整理的笔记；
- 一行一本书的简单文本。

最终都统一进入同一个入口：

`templates/booklist/已读书单模板.md`

---

## 多来源合并

当用户同时提供多个来源时，不要简单拼接。

推荐顺序：

1. 建立豆瓣 READ 主表；
2. 加入其他明确“已读”的记录；
3. 用下载历史补漏；
4. 作品级去重；
5. 同名消歧；
6. 标记来源；
7. 输出唯一 CURRENT。

建议保留一个 `source` 字段，例如：

```text
douban_read
zlibrary_history
manual
other_export
```

这样以后发现错误时，可以追溯“这本书为什么进入书单”。

---

## 隐私提醒

阅读记录可能包含账号昵称、个人评分、短评、时间信息等。

公开 GitHub 项目时：
- 不要提交自己的完整私人阅读历史；
- 不要提交登录 Cookie、Token、密码或浏览器会话；
- HTML 交给 AI 前可先检查是否包含不必要的账号信息；
- 示例数据应脱敏或使用自制样例。

---

## 完成条件

这一步的输出不是最终页面，而是一份可追溯、去重后的：

**权威书目 CURRENT**

只有 CURRENT 冻结后，才进入《读书小记》的内容和视觉生产。
